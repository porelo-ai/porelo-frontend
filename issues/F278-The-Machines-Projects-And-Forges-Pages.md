## Decided in the talk so far

- *Machines* stays the umbrella: this computer and the remote machines, rented or provided by someone; the proposal's *Hosts* page is the *Machines* page, with the remote machines as its rows (operator, 2026-10-30).
- A project admin may lock a developer in their project, beside the host admin's lock ([F272](README.md#f272)).
- The own identity stays under Settings ([F268](README.md#f268)).
- No tiles anywhere: every page is lists of rows, each row with a ⋮ menu holding its operations; a click on a row opens the item's own page, not a side panel (operator, draft 2, 2026-10-30).
- An item's page shows its own information with one ⋮ on top, then collapsible lists styled like the main list: a machine's *Projects* and *Persons*, a project's *Persons* and *Machines*, a forge's *Registry* and *Repositories* (operator, draft 2, 2026-10-30).
- Every list has a filter field in its header, filtering the rows below it: the top lists *Machines*, *Projects* and *Forges* and each collapsible list on an item's page (operator, 2026-10-30).
- The default project *Without a project*, for starting something by hand outside a real project, always exists on this computer and on every machine, so it always shows: in the *Projects* list as one row per machine and in each machine's *Projects* list, its ⋮ holding *Open* and *Start work*. It is never taken off a machine or locked, so its ⋮ offers neither (operator, 2026-10-30).

## Integration boundary

- `RegistryPageSource` supplies complete verified item/person snapshots, publishes an explicitly scoped change, and separately confirms its host application. `RegistryTarget` carries registry, host, and optional project; person actions also carry the selected verified login. No wire command, JSON response, or socket path is invented by the pages.
- `RegistryPageFeatures.operations` is empty by default. Its named switches cover refresh/file/select/create registry, admit/register/add/join, project lock/unlock/removal, host lock/unlock/account deletion, take-off/bring-state, push/pull, backup key, and lost-key replacement. An unavailable adapter exposes no action that would imply a working protocol.
- `RegistryPageItem.allowed` names currently permitted operations. `roleOperations` names additional operations this person's role can hold but cannot currently perform in this scope; operations in neither set are hidden. `authorities` maps an operation to its responsible role and verified person cards, including optional email. Refusals use only that operation's contacts, never scope administrators as a fallback; a missing role or missing contacts are named as unavailable information. These are page-adapter projections, with no assumed wire field names.
- `ForgeConnection.identityAccess` is the identity adapter; `setHostEntries` accepts transport-confirmed host forges, a local web endpoint, and an optional separate HTTP Git endpoint. Navigation matches scheme, host, port, and repository; endpoints on different loopback ports never share a project. `ForgeEntry.authentication` is the local settings field (`ssh` by default, or explicitly selected `token`); host endpoints are transient. Host URLs accept only HTTP loopback addresses without user information, query, or fragment.
- Existing project work, room, review, repository, server-placement, joining, and teardown operations remain connected where applicable. Registry-scoped projects use their scoped adapter actions instead of legacy placement/join/take-off forms. Typed developer and host-admin person entry points are absent from these pages.
- Prepared machines without any verified registry item retain their existing register/remove-project commands; verified machines use the scoped adapter paths. Daemon project shortcuts and finder commands refuse an opened machine or project that differs from the current daemon selection. Forge renaming preserves the existing authentication method; repository menus retain default-repository removal and trusted-machine tools.
- Registry publication and confirmed host application remain separate after failure and refresh. A new verified revision replaces an older local overlay. A tunnel withdrawal invalidates the selected host forge endpoint.

## Deferred

- Forgetting the open default machine does not leave an unwatched machine current: `Machines.current` reads from `all`, forgetting selects another watched machine, and `_commandForItem` skips the lookup when the opened machine differs.
- Live registry, access, publishing, key-recovery, and tunnel adapters, their protocol implementations, and the local VM walk against those services belong to the changes supplying those contracts.
- Machine-specific values in older guided walks and tooling need a separate documentation cleanup; those files are outside these page changes.
