# F274 — Push And Pull With The Central Forge Started By A Person

**Status:** Implementing. Estimated and Backlog (operator, 2026-10-30, sprint 6m).
**Size:** M - adds project actions, terminal-to-SSH delivery and central pull requests and reviews across app, client and host package boundaries.

**What must be true.** A person admitted to push sees *Push the approved main…* and *Take the central state…* on the project. Each runs porelo-host's push or pull on the host with the person's own token on standard input through the tunnel, read from their vault without asking, never written on the host, never on a command line. The answer is shown in the host's words. Pull requests and reviews on the central forge are read and made with the person's own token, started by that person, without webhooks.

## Why

One-click joining from signed state (operator, 2026-10-30), building block 3: the central forge's token never lies on the host.

## Plan

- **Red first:** `test/app/transfer_terminal_test.dart` reproduces early submission, raw progress forwarding and unbounded child cleanup; `test/app/central_reviews_test.dart` reproduces stale commands, disposed actions and masked Errors; `test/app/host_forge_refresh_test.dart` reproduces shared sync errors. Extend `packages/porelo_host/test/project_transfer_test.dart` with executable credential and SSH fakes and real PTYs to reproduce suppressed check failures, EOF and signal cleanup, echo during unlock and SSH, and missing explicit pinned options. Only the selected host command's standard input receives the synthetic credential. Check arguments, environment, files, callbacks and diagnostics for disclosure, including echoed input. `test/ui/project_actions_test.dart` proves unauthorized actions and unavailable local credentials start no host command.
- Add `ProjectTransfers` in `lib/src/app/project_transfers.dart` and explicit command factories in `lib/src/app/commands.dart`. Keep page layout and menu placement for the separate page implementation: *Push the approved main…* and *Take the central state…* belong on the project menu; central pull-request listing and creation belong there too, with reading and submitting reviews on the selected central request. Capture the verified host, current person, central forge, project and immutable repository list before credential delivery. Use verified push admission, independent of startup roles; block duplicate starts and retries after an unconfirmed result. A timed-out submission stays pending until the original operation settles, and reconciliation must read observed state after that; a concurrent newer operation invalidates the read. Negative and signal-derived SSH exits and provider failures after submission remain unconfirmed.
- `packages/porelo_host/lib/src/project_transfer.dart` defines `porelo-host-push <project> [repositories...]` and `porelo-host-push --pull <project> [repositories...]` in the admitted account's login shell. Its terminal feed uses the published host-card config and existing owned master, explicitly applies the shared pinned host policy including `BatchMode=yes`, disables fallback, and marks only shell-redacted host output for progress. Credential checks run directly in the terminal shell, with their stdout discarded rather than captured into the token feed. PTY echo stays off before the password prompt through SSH and is restored by EXIT, INT, TERM and HUP cleanup. `SecretsFile.projectTransferScripts` supplies exactly one `forge-central-token <base64 of token>` line. `OpenSsh` retains stdin-only redaction for its other callers, drains confirmed host refusals after a broken stdin pipe, and cleans up its owned child on callback failures. The host selects approved local `main`; pull brings central `main` to `central/main`, which reaches protected local `main` through a local pull request. No token goes into argv, environment, settings, history or a host file. The existing `forge-central-token` bring stop remains unchanged.
- `CentralTransferSource` takes public selections and returns public terminal results; no token-bearing callback enters Dart. `TransferTerminal` captures this interface instance's `Settings.secretsFile` and a visible terminal opener. Only `keepassxc-cli` inside that terminal reads the root entry `forge-central-token`, and the shell pipes its encoded line to SSH after local validation. Local config, terminal-spawn and child-exec failures remain retryable. Only the script's own marker immediately before SSH records submission; EOF, cancellation, timeouts and output loss before that marker remain retryable. Every result after that marker preserves uncertainty when the host answer is lost. Terminal shutdown, including output cancellation and waiting for the child, has a two-second bound; this releases the local controller without claiming that the remote operation settled. All failures, including Dart Errors, release busy state and retain uncertainty where submission was possible. Core supplies verified admission only; neither Core nor the platform token store supplies the transfer token.
- The current `Forge` clients have no central pull-request or review calls. Add the typed `CentralForgeReviews` capability, `CentralForgeSource` authentication boundary and explicit `CentralReviews` functions in `lib/src/app/central_reviews.dart`, tested with a stateful fake. Public app types describe pull requests, reviews, decisions and opaque page continuations; they are not assumed JSON fields. List, read, create and review only on the person's explicit request. A lost write response, including decoding Errors, blocks another write until an explicit successful read reconciles observed state. Known sanitized refusals keep their reasons. Programming Errors before submission and during reads propagate; only Errors after a write starts become uncertain results. Disposed controllers refuse reads, writes and stored commands before authentication, including delayed authentication callbacks. Stored commands expose current availability and dispatch the current refusal; write-state transitions notify menus. Gate approval remains local to the host forge.
- `ProjectCheck` and `Backups` take a `HostForgeRefresh` adapter for joined hosts. Their shell callers identify imported host cards. Every check and sync caller explicitly identifies whether it is a joined host; sync captures its own project and repository, returns its own result, and never shares the open backup listing's busy or problem state with overlapping syncs. Joined refresh and sync fail closed when that adapter is absent, and never fall back to the legacy `RefreshProjects` or `SyncUpstream` calls, whose contract does not identify a host-only target. Other machines retain their existing behavior. Add no webhook, background central transfer or unattended-token option.

## Acceptance

- Opening a project, refreshing its view or reconnecting starts no central transfer or central review request. Each explicit permitted action uses the captured project, repository, host and current person's credential once. A different role with push admission can use it; a role without that admission cannot.
- The process test proves stdin-only credential delivery on success, refusal, disconnect and echoed-input failure. A locked vault or missing token stops before host execution and is said without a secret input form. Host-side non-persistence is verified on a local VM once Machines provides the operation; a fake alone cannot prove it.
- A host refusal about approval, changed state or permission is shown without claiming success. Loss after submission is shown as an unconfirmed result, with no automatic replay. Refresh observed state after confirmed completion.
- Fake Gorge tests cover listing and reading pull requests and reviews, creating a pull request and submitting a review as the current person, and denied or lost responses. Merely viewing a project creates no pull request or review. A local VM check exercises real push and pull with the unlocked vault once the external contracts exist.

## Deferred

- Live central pull-request and review adapter: the existing `Forge` clients lack list/read/create pull requests and list/submit reviews, including their pagination and failure mappings.
- Joined host-forge refresh/sync adapter awaits a served contract that guarantees the central forge is not contacted.
- Project page wiring, progress/result presentation and central review forms belong to the separate page implementation; app functions and command factories are provided here.
- Host-side non-persistence and real unlocked-vault push/pull verification await the external implementations and local VM environment.
- Migration of the legacy bring/removal token entry is outside this transfer fix; the existing bring stop remains unchanged, while explicit transfers use the agreed root entry.
- The claim that a late completion clears submission during a newer transfer is not real: the submitted-key guard prevents that newer start until the original source future completes. Pending state while a source can still submit is intentional; the terminal's unbounded cleanup is fixed separately.
- The claim that transfer SSH had no BatchMode protection is not real for a published host config: the shared host policy already sets it. The transfer now also applies that same policy explicitly, as required.
- The claim that reconciliation catches a callback Error is not real: `readObservedState` already propagates it and leaves uncertainty intact. Authentication and read Error masking in `_ask` is fixed separately.
- Real OS-child termination and remote settlement after a hung-child timeout require a live environment; fake-channel tests establish only bounded local release and mandatory reconciliation.
- Existing personal login examples in `doc/walks/17-the-host-flow.json`, `integration_test/host_walk_test.dart` and `test/ui/project_room_test.dart` are outside this transfer fix.
- Existing machine-specific identifiers in `doc/walks/19-sprints-6e-to-6i-a-rented-server.json`, `doc/walks/21-sluice-tried-on-this-laptop.json` and `tool/walk_on_this_laptop.sh` are outside this transfer fix; the tracked-file scan found none in changed or new files.
