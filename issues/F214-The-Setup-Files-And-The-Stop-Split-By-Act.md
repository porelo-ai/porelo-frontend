# F214 — The Setup Files And The Stop Split By Act

**Status:** Implementing.
**Size:** M - [F197](README.md#f197)'s upload and [F199](README.md#f199)'s feed changed in place, by act, with their tests.

**What must be true.** The setup's files reach the person's own home on the host, owned by them, and the stop is fed by act: the host admin's root stop takes only the VPN key and the forge's certificate; a project admin's bring and a developer's join take their vault, keys and tokens in their own account, with no `sudo`.

## Why

Every person's part moves out of root: `porelo-host`'s setup directory becomes the person's own, and its stop gains an own-account mode.

## Plan

- **The upload** ([F197](README.md#f197)): `HostFiles` (`packages/porelo_host/lib/src/host_files.dart`) and `HostRun.setupPlace` take the person's own setup directory for bring and join, `.local/share/porelo-host/setup/<project>/` relative to their host home, defined once by `HostAct`. `HostRun.uploadSetupFiles` exposes the upload for the coming bring/join callers, requires the fixed names `machine.yml`, `project.bundle`, and `access.bundle`, with `access: {bundle: access.bundle}` in the machine file and an absolute `project.url` for that project bundle, installs the directory as `0700` and each file as `0600` without `sudo`, and checks SHA-256 in staging and in place. The caller starts `ansible-playbook -c local porelo.host.bring -e porelo_project=<project>` (or `porelo.host.join`) as that person, without sudo. The root path remains for today's combined project `up` until [F213](README.md#f213) replaces it.
- **The feed** ([F199](README.md#f199)): `hostStopFeedCommand` (`lib/src/app/host_stop_feed.dart`) requires `HostAct.root`, `ownAccount` or `legacyUp`, builds `porelo-host-stop --stdin` with or without `sudo`, and refuses a need the act does not take by name. Server preparation is root; combined project `up` retains its legacy sudo feed. Drive login and Matrix admission remain legacy handling. Own-account identities are refused until the secrets file supplies them; certificate requests stay privileged.
- **Refusals:** own-account feeds refuse root logins and require the interface's complete pinned SSH option sequence in its original order, without duplicates; root feeds allow the rental login because the stop runs through noninteractive sudo. Uploads refuse the root act and access bundles under the legacy act before remote work. Every own-account path uses the shared host-file name check and refuses names with traversal as `HostFilesRefused`; publication checks the name before any file changes. Staging uses `-upload-<project>`, which cannot be a project name because the name check refuses a leading hyphen. Own-account uploads require a nonempty normalized absolute home directory other than `/` that is not a link, derive every ancestor from the setup path, and use the checked absolute home for copies. The host creates personal accounts with Bash as their login shell. That shell's startup files and environment are the account's own and trusted. Remote scripts run directly through that Bash shell, with no redundant inner wrapper. The home reply is validated before staging is reserved, and unexpected shell stdout refuses any later step. Ambiguous replies permit only `rmdir` on a reservation; populated directories are preserved and reported. Files known to have been copied by this upload still receive scoped cleanup. One SSH session reserves setup exclusively, rechecks every directory, installs, and checks digests. Cleanup removes only known file names and uses `rmdir`, preserving unrelated entries and reporting directories it cannot safely clean.
- **Pathname race:** the account owner or root can still replace a checked path before a later filesystem operation, including during a copy or cleanup, redirecting it elsewhere with that account's permissions. The attacker already has the person's or root's filesystem access; rechecks narrow the window without descriptor-based directory operations. Revisit this design if an untrusted account can write the home or its setup ancestors. The legacy combined setup retains its root directory and cleanup behavior.
- **Red first:** the feed's tests that root refuses `keys` by name, own-account commands carry no `sudo` and refuse `wireguard`; upload tests that require the person's directory and both bundles before switching their caller from the combined `up` to the new upload method. Execute the upload commands in a private test home to verify modes, exact contents, digest failures, link refusals, and preservation of existing setup material. A redirected-ancestor fixture supplies the complete staging path and files, and must fail when the ancestor checks are disabled. Name checks, normalized paths, and staging disjoint from project directories have red-first tests. Transport tests check the login and absence of sudo; same-process UID comparisons cannot prove ownership enforcement.

## Acceptance

- A bring's files land in the admin's home, owner them, mode as `porelo-host` checks.
- A root stop never receives a vault passphrase or key; an own-account stop never a VPN key.
- Seen to fail: the feed test red before the act is named.
